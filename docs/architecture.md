# RepoPilot s01–s08 架构与学习说明

这是基础阶段的设计记录。当前 s01–s17 集成架构见 [runtime.md](runtime.md)，最新入口参数和权限行为以根目录 README 为准。

## 执行路径

`main.py` 检查目标 Git 仓库，创建工具注册表、独立 HookManager、模型客户端和 ContextManager。用户提交后触发 `UserPromptSubmit`，再把明确的当前请求传给 `Agent.run()`。

每次模型调用前，ContextManager 整理历史。模型返回工具调用时，Agent 依次解析参数、触发 `PreToolUse`、执行注册工具、触发 `PostToolUse`，最后追加全部结果。没有工具调用时触发 `Stop`；Hook 可以要求继续，但最多续行三次。主 Agent 每次任务最多 100 轮，子 Agent 最多 30 轮；达到限制会返回明确的停止信息。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `agent/loop.py` | 模型调用、顺序执行、配对结果、计划提醒、批次结束后压缩 |
| `agent/hooks.py` | 实例级事件注册与触发 |
| `agent/permission.py` | PreToolUse 权限策略与可注入的审批函数 |
| `agent/context.py` | 可恢复的输出和历史归档、摘要与配对边界保护 |
| `tools/planning.py` | 校验并管理完整任务清单，记录主动压缩请求 |
| `tools/task.py` | 通过工厂创建子 Agent，提供全新消息历史 |
| `tools/skills.py` | 扫描技能元数据、生成目录、按名称返回全文 |
| `llm/client.py` | 主任务模型请求和独立的事实摘要请求 |

## s05：计划作为显式状态

`todo_write` 接收完整清单，每次调用整体替换旧清单。状态必须是 `pending`、`in_progress` 或 `completed`。校验全部通过后才更新状态，因此非法请求不会损坏旧计划。版本号只在成功更新时增加，Agent 据此决定是否提醒。提醒每三轮触发一次，并带上当前计划；是否执行多步规划仍取决于模型遵循提示。

## s06：消息隔离的委派

`task(prompt)` 创建新的模型客户端、工具状态、HookManager、ContextManager 和消息列表。子 Agent 仍有基础读写工具、计划、技能和压缩能力，但没有 `task` 工具，因此只有一层委派。父子使用相同权限策略，各自的 Hook 注册表不共享；它们共享目标仓库和文件修改，不是进程或文件系统沙箱。父模型必须在子任务提示中明确提供目标和必要上下文，因为父消息不会复制给子模型。

## s07：按需知识加载

启动时扫描目标仓库 `skills/*/SKILL.md`，把名称和描述加入系统提示；`load_skill` 只通过名称查询注册表，不把模型输入当文件路径。扫描会拒绝越出技能目录的符号链接和重复名称。完整说明只在工具结果中出现，启动后修改技能需要重启以重新扫描。当前读取并缓存全文，但不会把全文提前发给模型。

## s08：OpenAI 消息格式下的压缩

这里保留项目原有 OpenAI-compatible 消息格式：`assistant.tool_calls` 后跟多个 `role=tool` 消息。压缩切点向前移到对应 assistant，避免孤立 tool 结果。

管线采用以下顺序：

1. 最新工具批次超过 200,000 字符时，优先把超过 30,000 字符的结果落盘，保留 1,000 字符预览。
2. 历史超过 50 条时，保存完整历史，保留最近约 46 条和归档标记。标记包含当前请求与计划；切点可能向前移动，实际条数可以略多。
3. 历史超过 50,000 字符时，缩短已经读取过的旧工具结果，保留最近三条已读取结果。仍超限时，也会转存其他长结果并保留预览。
4. 仍超限时，用独立模型调用生成事实摘要，保留当前请求、完整计划和原始记录路径，再替换历史。

`compact` 工具只记录请求；必须先完成整个工具批次、追加每个调用的结果，才真正摘要。模型 API 明确报上下文过长时，总结旧历史并保留最近约五条消息，重试一次；重试失败继续抛出异常。摘要失败或为空时不替换原历史。

字符阈值只是估算，不包含系统提示和工具 schema 的 token 成本。归档标记可以恢复原文，但模型不一定主动读取；模型摘要也可能遗漏细节。保存到磁盘的是归档记录，尚不是 s09 的跨会话记忆。

## 验证与手动实验

运行 `python -m unittest discover -s tests -v`。测试覆盖文件边界、编辑歧义、Hook 拦截、任务清单原子校验、子任务消息隔离、技能按需加载、输出落盘、归档配对、主动压缩闭合批次和超限单次重试。

手动验证可在临时 Git 仓库中放置 README、简单程序与测试，再让 Agent 先规划、运行失败测试、修改程序并重跑。也可以要求子 Agent 调查一个明确文件，观察父消息只收到总结；主动调用 compact 后，检查 `.repopilot/runs/` 的记录与后续模型行为。真实模型的工作效果需要这些端到端实验验证，目前自动化测试不代表复杂任务完成率。
