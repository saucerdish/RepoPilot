## 发现

配置任务修复了跨模块优先级与类型解析，外部公开测试和七个独立验收方法通过。但模型多次添加目录切换、附加命令，或改变路径分隔符，没有成功使用精确授权的测试命令。它最终报告不能执行验证，Goal 为 impossible。保留此首次失败，不能将外部代跑成功算作 Agent 自主完成。

分页任务通过了空页、falsy 游标、循环保护和错误传播验收。金额任务新增 CLI，并通过 Decimal 舍入、参数校验、JSON 输出和非法输入退出码验收。这些任务也出现过未授权命令尝试，说明测试执行的稳定性仍需改善。

上下文任务注入约 90 KB 历史诊断数据，实际记录一次 summary 调用和一个历史归档。Goal 检查发现 bool 校验未满足要求后，Agent 修改实现并重新测试，最终通过独立验收。它证明这一样例上的压缩与续行链路有效，不能由此推断任意长任务的恢复成功率。

## 可复核性与限制

首次监督进程在配置任务评分时，因正常结果的 error=null 触发类型错误而退出。修复评分器并通过回归测试后，使用 --resume-run 继续原运行：配置任务复用已保存的 worker 结果，仅重跑外部验收，未重跑模型；其余任务各执行一次。原配置任务没有初始 SHA256 清单，使用初始 Git 提交与修改文件范围检查保护文件；后续任务同时使用 SHA256 和 Git 检查。这个监督故障属于评测器问题，和配置任务自身的权限失败分别记录。

最终本地自动化回归测试 42/42 通过。真实评测的 75% 完整任务通过率只描述这四个生成仓库、该模型和本次配置；样本少、未多次重复，也没有基础循环消融组，不能写成大型真实仓库完成率或能力提升百分比。

复现方法见 [性能测试说明](benchmark.md)。优先改进方向是给 Agent 提供结构化的测试执行入口，减少精确 shell 字符串匹配带来的失败，然后固定模型与任务重复评测。
